> **v3 — complete end-to-end guide.** Merges the original Databricks deployment workflow (wheel build, MLflow registration, serving endpoint, querying, batch inference) with the additions from the official *Swift Hybrid Postal Address Structuring Installation & User Guide*, release 1.0.0 (01 December 2025).
>
> Sources: [Swift-SC/iso20022-address-structuring](https://github.com/Swift-SC/iso20022-address-structuring) (GitHub) · Swift.com download centre archives · official Installation & User Guide PDF.

---

## 1. What the Model Is

An **offline-runnable, lightweight NLP system** (deliberately *not* an LLM — a few million parameters) that infers structured **Town** and **Country** from unstructured legacy address content found in client databases and corporate payment files, supporting the ISO 20022 migration and the November 2026 CBPR+ structured/hybrid address requirement.

Three sequential components plus a post-processor:

| Stage | Component | Notes |
|---|---|---|
| 1 | **CRF + Transformer** (char-level tokens, BIO tagging, order-2 CRF) + a 3-layer **MLP country predictor** | Trained on synthetic data generated from anonymised payment templates (Faker, OpenStreetMap, GeoNames) |
| 2 | **Fuzzy matcher** against the reference dataset | Max Levenshtein distance 1 (one typo tolerated) |
| 3 | **Postcode regex matcher** | Exact match against postcode reference data |
| 4 | **Rule-based bonus/malus post-processing** | Flags (e.g. `IS_IN_LAST_THIRD`, `MLP_STRONGLY_AGREES`) adjust scores; top-2 combinations output |

**Operational profile:** Python ≥ 3.12, PyTorch ≥ 2.8.0, ~4 GB RAM, CPU-optimised (GPU optional), fully offline at inference — no internet/API connectivity required. **Stateless**, so it scales horizontally without diminishing returns.

## 3. Prerequisites

- Databricks workspace with **Unity Catalog** and **Model Serving** enabled.
- Cluster on **DBR 16.x or later** (Python 3.12 — hard requirement; logging from 3.11 produces a broken serving container).
- UC Volumes:
  - `/Volumes/<catalog>/<schema>/libs/` — wheel
  - `/Volumes/<catalog>/<schema>/swift_addr/raw/` — pinned raw dumps
  - `/Volumes/<catalog>/<schema>/swift_addr/resources/<version>/` — generated reference data + weights
- Permissions: `CREATE MODEL` on the schema, write on the Volumes, `CAN MANAGE` on serving endpoints.

## 5. Phase 1 — Build the Reference Datasets

No runtime downloads occur — this is a **one-time offline preparation** (plus periodic refresh). Run on a DBR 16.x cluster/job; write outputs to a **versioned** Volume path.

### 5.1 GeoNames town/country dataset → `resources/raw/geonames/`

From the GeoNames exports page, download, extract, and place:

- `allCountries.zip` (extracted)
- `countryInfo.txt`
- `alternateNamesV2.zip` (extracted)

```bash
python data_structuring/preprocessing/preprocess_geonames_towns.py
python data_structuring/preprocessing/preprocess_geonames_countries.py
```

Output paths are read from the database configuration in `config.py`; generated files land in `resources/`.

### 5.2 GeoNames postal codes dataset → `resources/raw/postcodes/`

From the GeoNames **postal codes** exports page, download, extract, and place:

- `allCountries.zip` (extracted)
- `CA_full.csv.zip`, `GB_full.csv.zip`, `NL_full.csv.zip` (extracted)

```bash
python data_structuring/preprocessing/preprocess_geonames_postcodes.py
```

Generates the postcode matching files in `resources/post_codes/`.

### 5.3 REST Countries dataset → `resources/raw/restCountries/`

Download `countriesV3.1.json`, place it in the folder, then:

```bash
python data_structuring/preprocessing/preprocess_rest_countries.py
```

Generates `country_specs.json` in `resources/misc/` (used for matching website domains and phone numbers).

> **Refresh cadence:** GeoNames updates continuously; Swift notes benchmark accuracy can drift with reference updates. Pin raw dumps in a Volume for reproducible rebuilds; refresh quarterly and re-run the §11 validation gate.

## 6. Phase 2 — Build and Stage the Wheel

The repo has a complete `pyproject.toml` (package `swift_address_structuring`). The wheel contains **code only** — no weights, no reference data.

```bash
git clone https://github.com/Swift-SC/iso20022-address-structuring.git   # or unpack the Swift.com codebase archive
cd iso20022-address-structuring
pip install build
python -m build --wheel
# → dist/swift_address_structuring-1.0.2-py3-none-any.whl  (~210 KB, pure Python)

databricks fs cp dist/swift_address_structuring-1.0.2-py3-none-any.whl \
  dbfs:/Volumes/<catalog>/<schema>/libs/
```

The wheel declares all runtime dependencies (torch 2.8.0, polars, RapidFuzz, safetensors, …) in its metadata, so it can be the **single** pip requirement when logging the model. It also installs an `iso_run` CLI for cluster smoke tests.

> For supply-chain hygiene, mirror the repo into GHES and build/publish the wheel from a source you control.

## 7. Phase 3 — MLflow Pyfunc Wrapper, Log & Register

Uses the **officially documented** `DataStructuring` API (list of address strings + four config objects):

```python
import mlflow
import pandas as pd
from mlflow.models import infer_signature

class SwiftAddressModel(mlflow.pyfunc.PythonModel):
    def load_context(self, context):
        import os
        res = context.artifacts["resources"]
        # Relocate all resource paths to the bundled artifacts.
        os.environ["ds_prefix_folder_path"] = res

        from data_structuring.run import DataStructuring
        from data_structuring.config import (CRFConfig, FuzzyMatchConfig,
                                             PostProcessingConfig, DatabaseConfig)
        self.ds = DataStructuring(
            crf_config=CRFConfig(),
            fuzzy_match_config=FuzzyMatchConfig(),
            post_processing_config=PostProcessingConfig(),
            database_config=DatabaseConfig(),
        )
        from data_structuring.components.Runners import ResultPostProcessing
        self._post = ResultPostProcessing

    def predict(self, context, model_input, params=None):
        debug = bool(params.get("debug", False)) if params else False
        addresses = model_input["address"].tolist()
        results = self.ds.run(addresses, batch_size=1024, show_progress=False)
        # Flatten to the documented 1th_/2th_ column schema (see §10).
        final_df, _ = self._post.save_list_as_human_readable_csv(
            results, file_name="/tmp/ds_output.csv", debug=debug)
        return final_df


mlflow.set_registry_uri("databricks-uc")

example = pd.DataFrame({"address": [
    "XX012345678901234567\nMARIA KUMAR\n42 MAIN ST A 5TH AVE\nNEW YORK, NY 10001, US"
]})

RESOURCES = "/Volumes/<catalog>/<schema>/swift_addr/resources/<version>"
WHEEL     = "/Volumes/<catalog>/<schema>/libs/swift_address_structuring-1.0.2-py3-none-any.whl"

with mlflow.start_run(run_name="swift-addr-structuring"):
    mlflow.pyfunc.log_model(
        artifact_path="model",
        python_model=SwiftAddressModel(),
        artifacts={"resources": RESOURCES},     # copied INTO the model package → hermetic container
        pip_requirements=[WHEEL],               # wheel metadata pulls the rest
        signature=infer_signature(example),
        registered_model_name="<catalog>.<schema>.swift_address_structuring",
    )
```

Notes:

- Log from a **Python 3.12** runtime so the captured environment matches.
- `params={"debug": true}` toggles explainability columns per request (no runtime cost, wider output).
- Verify the import paths and `save_list_as_human_readable_csv` signature against the release you pin (guide = 1.0.0; GitHub = 1.0.2).
- Tag the model version with both **code release** and **resources snapshot** (e.g. `code=1.0.2`, `resources=2026-06`).

## 8. Phase 4 — Create the Serving Endpoint

### 8.1 Terraform

```hcl
resource "databricks_model_serving" "swift_addr" {
  name = "swift-address-structuring"

  config {
    served_entities {
      entity_name           = "<catalog>.<schema>.swift_address_structuring"
      entity_version        = "1"
      workload_size         = "Medium"   # ≥4 GB working set; Small is likely too tight
      workload_type         = "CPU"      # model is CPU-optimised; GPU unnecessary
      scale_to_zero_enabled = true       # set false if cold-start latency matters
    }

    traffic_config {
      routes {
        served_model_name  = "swift_address_structuring-1"
        traffic_percentage = 100
      }
    }
  }
}
```

(Equivalently: Serving UI → Create endpoint → select the UC model, or `POST /api/2.0/serving-endpoints`.)

### 8.2 Sizing, scaling, cold start

- Reference data + torch weights load in `load_context` → expect **minutes** of cold start when scaling from zero. For real-time payment-repair flows, keep `scale_to_zero_enabled = false`.
- Start with **Medium CPU**; right-size from endpoint metrics.
- The model is **stateless** — prefer horizontal scaling (larger workload size / more concurrency) over shrinking reference data. If throughput is still insufficient, `town_minimal_population` trims the reference set proportionally to speed, at an accuracy cost (§12).

### 8.3 Rollout pattern

Blue/green via `traffic_config`: register the new version (new code release or refreshed resources), add it as a second served entity at low traffic %, run the §11 benchmark gate against it, then shift to 100%.

## 10. Output Schema (serving response / Delta contract)

### Business columns (always present)

| Column | Description |
|---|---|
| `address` | Original input string |
| `1th_best_country` | Top country prediction, as spelled in the input |
| `1th_best_country_confidence` | Confidence, **string percent** (e.g. `'98.25%'`) |
| `1th_best_country_resolved_code` | Resolved ISO 3166-1 alpha-2 code |
| `1th_inferred_country_resolved_code` | Country code inferred **from the town** prediction (if enabled) |
| `1th_best_town` / `_confidence` / `_resolved` | Top town as written / confidence / reference-DB spelling |
| `2th_*` | Second-best combination, same fields |

Semantics to handle downstream:

- **`NO COUNTRY`** appears when a combination has a town but no explicit country (low fixed confidence, e.g. `15.0%`); the inferred-country column may still carry a useful code.
- The same candidate can repeat across 1st/2nd combinations.
- Confidences are percent **strings** — cast to `DOUBLE` after stripping `%` in your Delta schema.

### Debug columns (`params.debug = true`)

`detailed_country_matches`, `detailed_town_matches`, `crf_prediction_country/town/postal_code`, `crf_spans`, `country_head_prediction` + `_confidence`, `ibans`.

**Routing rule (Swift best practice):** automate on high-confidence predictions; route low-confidence results to manual review. Review debug output periodically — recurring ambiguities usually indicate reference-data gaps.

## 12. Batch Inference Alternative (recommended for bulk cleansing)

The model's primary use cases — cleansing client databases and repairing corporate payment files — are **batch** workloads. For Delta-table-scale runs, use the registered model as a Spark UDF in a job instead of the REST endpoint:

```python
import mlflow
from pyspark.sql import functions as F

mlflow.set_registry_uri("databricks-uc")

udf = mlflow.pyfunc.spark_udf(
    spark,
    model_uri="models:/<catalog>.<schema>.swift_address_structuring/1",
    result_type=(
        "address string, 1th_best_country string, 1th_best_country_confidence string, "
        "1th_best_country_resolved_code string, 1th_inferred_country_resolved_code string, "
        "1th_best_town string, 1th_best_town_confidence string, 1th_best_town_resolved string, "
        "2th_best_country string, 2th_best_country_confidence string, "
        "2th_best_country_resolved_code string, 2th_inferred_country_resolved_code string, "
        "2th_best_town string, 2th_best_town_confidence string, 2th_best_town_resolved string"
    ),
)

df = spark.table("<catalog>.<schema>.customer_addresses")          # pre-normalised per §13
out = df.withColumn("structured", udf(F.struct("address")))
out.write.mode("overwrite").saveAsTable("<catalog>.<schema>.customer_addresses_structured")
```

Rule of thumb: **endpoint** for interactive/real-time flows (payment repair UI, onboarding validation); **spark_udf job** for backfills and periodic cleansing. Verify the struct field names against actual model output on your pinned release before relying on the schema above.

## 13. Input Contract (enforce upstream of both paths)

Accuracy depends heavily on input shape — the CRF is extensively trained on **MT 103 field 50/59** structures.

1. Tabular input uses a column labelled **`address`**, one address per row; multi-line addresses use embedded newlines.
2. If town, postal code, and/or country are known, place them on the **last line, in that order**.
3. Account number and holder name go on the **first and second lines**; if unknown, use Swift's training placeholders:

   ```
   XX012345678901234567
   MARIA KUMAR
   <address line>
   <address line, with TOWN POSTCODE COUNTRY last>
   ```

4. **Max 35 characters per address line** — split longer lines (the guide ships a reference `split_every_35th_char` implementation worth porting into ingestion).
5. **Romanise non-Latin scripts** (e.g. with `anyascii`) before submission.
6. If data is partially structured, merge known structured elements into the unstructured string per rules 2–3.

Implement these as a deterministic pre-processing function in the ingestion layer so the endpoint and batch paths both receive normalised input.

## 14. Model Configuration & Tuning

| Parameter | Effect | Trade-off |
|---|---|---|
| `enable_extended_data` | Adds the OpenStreetMap dataset for more candidates | Slower inference |
| `town_minimal_population` | Filters reference DB by town population | Speed ↑, recall ↓ for small towns |
| `force_countries` | Full reference DB for listed countries (overrides threshold) | Targeted recall (e.g. `["NZ","AU","CN","IN"]`) |
| `force_country_groupings` | Same, by grouping (Europe, EMEA, …) | Coarser |
| `show_inferred_country` | Emit inferred-country column when only a town is found | Extra repair signal |
| Flag bonus/malus weights | Post-processing score tuning | Advanced; defaults recommended |

If specific geographies underperform, **amend or substitute the reference data** (keeping GeoNames format) — usually a cleaner fix than tuning weights.
